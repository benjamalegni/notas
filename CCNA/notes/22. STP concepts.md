Spanning tree protocol: es un protocolo especialmente disenado para eliminar layer 2 loops en la red

la redundancia es una parte importante del diseno jerarquico para eliminar puntos unicos de fallos y prevenir la disrupcion de los servicios de red para los usuarios. las redes redundantes requiren la adicion de caminos fisicos, pero la redundancia logica tambien debera ser parte del diseno

## STP
previene los loops en la red, permitiendo la redundancia.
IEEE 802.1D es el bridging standard original para STP 

## links switch redundantes
cuando existen multiples caminos entre dos dispositivos en una red (y no se usa STP), un loop puede resultar en una **inestabilidad de la tabla MAC**, link saturation, alta utilizacion de CPU en switches y end-devices, resultando en una red inusable.

en estos casos:
- en IPv4 los routers disminuiran el TTL
- en IPv6 disminuiran el campo hop limit
cuando estos campos llegan a 0, el router dropea el paquete

### broadcast storm
es cuando un gran numero de broadcasts abruma la red durante un periodo especifico de tiempo, pueden **desactivar la red por segundos**
- puede ser causados por ARP reqs

### spanning tree algorithm
STP se asegura de que solamente **haya un camino logico entre todos los destinos en la red al bloquear intencionalmente caminos redundantes que puedan causar loops**

cuando un link falla:
- STP recalcula los caminos y desbloquea los puertos necesarios para permitir al camino redundante convertirse activo

**STP mantiene algunos puertos en "blocking state"**

# operaciones de STP
1. Elect the root bridge: el jefe (switch central) que sirve como punto de referencia principal para calcular todas las rutas
2. Elect the root ports: es el puerto de un switch que ofrece el camino mas directo y de menor costo hacia el root bridge
3. Elect designated ports: es el responsable de reenviar trafico hacia afuera del root bridge
4. Elect alternate (blocked) ports: es un puerto en estado de bloqueo que ofrece una ruta de respaldo hacia el root bridge

en STP, los **switches usan bridge protocol data units (BPDUs) para compartir info acerca de ellos mismos y sus conexiones**
BPDUs eligen
- root bridge
- root ports
- designated ports
- alternate ports

bridge priority:
- valor por default 32768. rango de 0 a 61440 en incrementos de 4096
	- un valor bajo es preferible

extended system ID
- valor decimal anadido al bridge priority para identificar **la VLAN** para ese BPDU. 
- las primeras implementaciones de IEEE 802.1D fueron disenadas para redes que no usaran VLANs. luego si se anadio al estandard
	- el extended system ID no estaban incluidos en sus BPDUs
- este campo tambien soporta implementaciones mas modernas de STP , como rapid STP (RSTP)

mac address:
- cuando dos switches son configurados con la misma prioridad y tienen el mismo extended system ID, **el switch que tenga la menor direccion MAC, expresada en hexa, va a tener el menor BID**

### STP timers y port states
la convergencia STP requiere 3 timers
- hello timer: es el intervalo entre BPDUs, el default es 2 segs. admite numeros entre el rango 1-10
- forward delay timer: el tiempo que gasta escuchando y aprendiendo estado, default 15 segs. admite numeros entre 4 y 30 segs
- max age timer: es la longitud maxima de tiempo que un switch espera antes de intentar cambiar la topologia STP, default 20 segs. puede ser modificada al rango 6-40 segundos

### portFast y BPDU guard
cuando un dispositivo se conecta a un puerto switch o cuando un switch se enciende, **el puerto switch se va a estado de escucha y de aprendizaje**
- en cada uno de esos estados, espera 15 segs, dando un total de 30 segs
este delay presenta un problema para clientes DHCP intentando descubrir un servidor DHCP

con PortFast, las transiciones del puerto comienzan inmediatamente, evitando esos 30 segundos de espera
![[Pasted image 20260923084156.png]]

en una configuracion usando PortFast, los BPDUs nunca deben ser recibidos en un switch que tenga activado PortFast, **porque indicaria que otro bridge o switch esta conectado al puerto**, esto potencialmente causaria un loop
BPDU guard inmediatamente pone el puerto switch en errdisabled en cualquier BPDU. esto proteje ante loops portenciales **al apagar el puerto**
